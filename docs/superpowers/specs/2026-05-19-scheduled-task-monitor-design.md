# 定时任务监控模块设计

## 背景

后台已经支持创建定时爬取和定时更新任务，但任务是否按预期运行、最近是否有扫描、是否有到期未触发任务，目前只能从任务历史和数据库间接判断。此前还出现过旧 Celery beat 内置任务绕过后台配置的问题，说明需要一个可视化监控模块帮助排查调度器状态。

## 目标

在“定时任务管理”页新增监控模块，实时展示调度器运行状态、任务触发情况、最近生成任务、失败风险和来源聚合。后端提供一个监控聚合接口，前端定时轮询。

## 方案

后端新增 `scheduled_task_runs` 表记录每次调度器扫描：

- `started_at` / `finished_at`
- `status`
- `due_count`
- `dispatched_count`
- `failed_count`
- `triggered_task_ids`
- `error_message`

`run_due_scheduled_tasks` 每分钟执行时写入一条 run record。监控接口 `GET /api/admin/scheduled-tasks/monitor` 聚合：

- 当前服务器时间。
- 调度器健康状态：`healthy`、`delayed`、`stalled`。
- 最近扫描时间和扫描结果。
- 已启用、暂停、到期待触发任务数。
- 最近 24 小时由定时任务创建的 `crawl_tasks` 数量、成功数、失败数、运行中数。
- 最近 10 条由定时任务创建的任务。
- 最近 10 条调度器扫描记录。

前端在定时任务管理页顶部展示监控面板，每 5 秒刷新一次。视觉风格沿用后台 Apple 风格：轻量卡片、状态标签、紧凑表格，不做重型图表。

## 非目标

- 不接入 Celery inspect。第一版用数据库状态推断，避免 worker 在线查询不稳定。
- 不做 WebSocket。轮询足够支撑当前后台使用。
- 不做告警推送。只在页面内显示诊断状态。

## 健康判断

- `healthy`：最近扫描在 2 分钟内。
- `delayed`：最近扫描在 2 到 5 分钟内，或存在已到期未触发任务。
- `stalled`：没有扫描记录，或最近扫描超过 5 分钟。

如果没有启用任务但调度器仍有心跳，也显示健康。

## 验证

- 后端 API 测试覆盖监控聚合、扫描记录写入。
- Celery beat 配置测试继续确保只保留 `run_scheduled_tasks`。
- 前端构建通过。
